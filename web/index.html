What it finds

Four sections, one honest capacity bar.

The bar at the top of each section splits your disk by what’s actually there, largest first, so a glance tells you which section is worth opening.

Developer

Derived Data, Device Support, documentation caches, Xcode downloads and archives. Then Homebrew, SPM, CocoaPods, Carthage, Gradle, npm, Yarn, pnpm, Bun, Deno, pip, Cargo, Go, Maven, NuGet, Playwright, rustup, ccache, Poetry, uv and more.

AI Tools

Claude Code, Codex, Gemini CLI, Cursor and Windsurf caches — plus the models you pulled with Ollama and the runtimes LM Studio downloaded, usually the largest things here. Credentials and memory files are never listed.

Browsers

Page and script caches for Chrome, Safari, Firefox, Edge, Brave and Arc — rebuilt as you browse. History, passwords, bookmarks, profiles and open tabs live elsewhere and are never touched.

Creative

Premiere Pro and Media Encoder media caches, After Effects disk cache, Photoshop scratch, Camera Raw previews, Lightroom video cache and Ableton’s decoding cache. Working caches only — never project files or exports.

Menu bar, at a glance Free

Free space in your menu bar and one button that clears the regenerable Xcode caches. It cannot touch simulators, archives or AI session history — ever. A notification fires when free space drops below a threshold you set.

Applications

Uninstall an app, and the mess it leaves behind.

Every app above is one click from gone — along with its caches, containers, preferences, saved state and launch agents. All of it goes to the Trash, so a guess is always reversible.

  • Three levels of confidence. A bundle identifier is certain. An exact filename is likely. A whole-word name match is only possible — and labelled as such.
  • It won’t take a neighbour’s data. Word boundaries so “Steam” never claims SteamVR, a four-character minimum, and shared vendor folders are off limits.
  • Inside Containers, only a bundle id counts. Matching an app’s name against a reverse-DNS string is a coincidence, not evidence.
  • System apps are refused outright. They can’t be uninstalled, so listing your Mail data would be pointless and alarming.
Developer

Xcode never tells you it kept all this.

Derived Data, device symbols, simulator devices, package caches for every toolchain you have ever installed. It accumulates in folders Finder does not show, and nothing ever clears it.

  • Simulators are usually the biggest thing you own. Whole device sets, with their installed apps and data, measured exactly.
  • Deleted through simctl, never by removing folders, so CoreSimulator’s registry stays consistent instead of pointing at devices that no longer exist.
  • Irreversible items are flagged in red. Archives take the dSYMs you need to read crash reports from versions you already shipped.
  • Expand anything to delete a single stale SDK version or one project’s build output, rather than the lot.
AI Tools

The caches no other cleaner knows exist.

Claude Code, Codex, Cursor, Windsurf, Gemini CLI, Ollama, LM Studio. These tools arrived faster than the cleaners did, and they are quietly some of the largest things on a developer’s Mac.

  • Session history is found, measured and flagged — per-project transcripts, backups, and the file history that powers rewinding an edit. Deleting it loses resume, search and undo, so it is marked and never touched automatically.
  • Model weights you chose to download. Ollama pulls and LM Studio runtimes, usually gigabytes, listed by name.
  • Credentials and memory files are never listed. Only caches, logs, scratch data and models.
  • A general Mac cleaner sees none of this — these paths are days or weeks old and are not in anybody’s built-in list.
Pro

Your own folders. Your own schedule.

Every developer has a folder the catalogue will never know about — a render output, a scratch directory, a build server’s dumping ground. Custom Categories give it a section in the sidebar; Automation keeps it clear without you looking.

  • A section that’s yours. Name it, pick an SF Symbol and a colour, point it at a root folder and tick the folders inside it to track.
  • The root folder is never cleaned itself — only what you tick inside it, which is why choosing a broad folder is safe.
  • Rules are fenced to safe targets only. Archives, session history and simulator devices can never be reached by a rule, re-checked every time one runs.
  • Configure before you pay. The editor and the rules table open and work for everyone. Only pressing Save is gated.
  • Synced through iCloud. Your categories and rules follow you between Macs. Nothing is uploaded but the definitions.

Safety

A disk cleaner earns trust by what it refuses to do.

These aren’t settings. They’re enforced in the app’s own model and pinned by its test suite, so reorganising the interface cannot widen what a button can reach.

Nothing is pre-selected

Every checkbox on every section starts empty. Each section’s button cleans only that section — ticking something under AI Tools can never be swept up by cleaning Developer.

It will not delete itself

The app refuses any folder containing its own bundle. A debug build lives inside Derived Data — exactly the sort of folder it cleans.

Symlinks are skipped

A symlinked location is never followed to wherever it points. It is skipped and left alone.

Permission errors are reported

A folder the app cannot read shows up as a failure with a pointer to Full Disk Access — never as an empty folder with nothing to clean.

Simulators go through simctl

Devices are shut down and deleted by UDID using Apple’s own tool, never by removing folders, so CoreSimulator’s registry stays consistent.

The one-click clean is fenced

Eligibility is an explicit per-item flag, never inferred from which section something sits on. Simulators, archives and session history are unreachable without a deliberate tick.

It waits for your build

An unattended clean defers while Xcode is running, and the confirmation dialog warns you when Xcode, Android Studio or a JetBrains IDE is open.

The newest symbols are spared

The unattended clean keeps the newest Device Support build — usually the device you’re debugging, and several minutes to re-copy.

Sizes are the space you get back

Measured as allocated blocks, the way du counts. There is a test that checks the app’s numbers against du directly.

Stop means stop cleanly

Stopping a clean takes effect between items, never inside one, so every item is either fully removed or untouched. It ends a clean early; it never half-deletes one.

Uninstalls go to the Trash

A name match is a guess, and a guess must be reversible. So the app reports “moved to the Trash”, never “freed” — the space returns when you empty it.

Irreversible items are marked

Archives take their dSYMs, so old crash reports stay unreadable. Simulators take their apps and data. Session history can’t be resumed. All three are flagged and excluded from every automatic path.

One honest caveat. Like every tool of this kind, Easy Sweep relies on Xcode’s undocumented folder layout, which Apple can change at any time. Have a backup. Lockfiles, SDK installs, emulator images and editor workspace state are deliberately absent from the catalogue — those are not caches, and losing them costs you real work.
Privacy

No account, no tracking, nothing to send.

Most apps that clean your Mac want you to sign in first. Easy Sweep has no sign-up, no analytics and nothing to opt out of — and the free app never opens a network connection at all.

No analytics, ever

No telemetry, no usage reporting, no crash reporter, no advertising or attribution SDKs — none of it, in either edition. There is no account to create, so there is nothing to log in to and nothing to delete.

The free app works entirely offline

Not an update ping, not a first-run call home, not a licence check. If you never buy Pro, Easy Sweep has no reason to open a connection — so it doesn’t. Run it on a Mac that has never seen a network and nothing changes.

Nothing about your disk leaves it

Which folders you have, what they contain, how big they are, which apps you installed or removed — all of it is worked out on your Mac and none of it is transmitted. Diagnostics go to the standard macOS log, on your Mac, where you can read them.

You can audit what it targets

Every category it scans is defined in public, under the MIT licence. Each path is written down where you can read it before installing anything, and contributions are welcome — so the list is checkable rather than merely promised.

Your licence never syncs

A direct licence key lives in the macOS Keychain, explicitly marked not to sync. A key that travelled through iCloud would quietly activate every Mac it reached, spending seats you never chose to spend.

Pro’s two connections, named

Buying Pro directly adds a licence check, which sends the key and a machine identifier and nothing else. Using Custom Categories or Automation syncs those definitions — names, icons, the folder paths you chose — through your own iCloud account, never their contents. That is the complete list.

Said plainly: we have no server, no database and no record of you. There is no privacy setting to find because there is nothing collected to turn off. The privacy policy spells out every request the app can make, and it is a short page.

Questions

Reasonable things to ask before you let something delete files.

Which edition should I get?

The direct download, unless you specifically want App Store updates and billing. It reaches your caches without asking and can remove an app bundle outright. The App Store edition is sandboxed by Apple’s rules, which means granting folder access once and living with not being able to delete other apps’ bundles.

Is it safe to clean everything it shows me?

Almost. Anything marked with a warning cannot be recovered: archives take the dSYMs you need to read crash reports from versions you already shipped, simulator devices take their installed apps and data, and AI session history can no longer be resumed or searched.

Everything else regenerates itself. The only cost is the time to rebuild or re-download it.

Why does it want access to my home folder?

Only the App Store edition asks. Dot-directory caches — ~/.npm, ~/.cargo, ~/.gradle — are direct children of your home folder, so nothing narrower covers them. The panel is held to exactly the folder being asked for, so you cannot accidentally grant the wrong one and end up with a section that looks broken.

The direct download is not sandboxed and never asks. Some locations under /Library may need Full Disk Access, which macOS asks for in System Settings.

Will it delete my simulators?

Only if you tick them yourself. Simulators appear under Developer because they live inside Xcode’s folder, but eligibility for any automatic clean is a per-item flag rather than something inferred from the section — so the menu bar button, the low-space notification and every automation rule are all structurally unable to reach them.

Do the numbers match what I actually get back?

Yes. Sizes are allocated blocks, the same measure du uses, which is the space the filesystem actually returns. There is a test that compares the app’s figures against du output directly.

The one exception is app uninstalls, which move files to the Trash rather than deleting them. Those are reported as “moved to the Trash” and never counted as freed space, because the bytes don’t come back until you empty it.

Does it send anything anywhere?

No analytics, no telemetry, no account. The app makes exactly two kinds of network request, both only if you choose them: a licence check when you activate or validate a direct purchase, and iCloud key-value sync for your own categories and rules if you use Pro. Nothing about what you scanned or deleted leaves your Mac. See the privacy policy.

What happens if my licence check fails?

Nothing. Offline, a timeout, a server error — none of them touch your entitlement. It is revoked only on an explicit answer that the licence has been disabled, expired or is not recognised. It’s a one-time purchase, so revalidation can only ever discover a refund, and that is a far cheaper failure than locking someone out of a paid feature on a plane.

If I stop paying, do I lose my folders and rules?

You can’t stop paying — it’s one payment. But if an entitlement ever does lapse, nothing is deleted. Your categories and rules stay stored and stay visible; they just can’t be added to, cleaned or run until it’s restored.

Can I see exactly which folders it targets?

Yes — all of them. Every category Easy Sweep scans is defined in a public repository under the MIT licence, so you can read every path it targets before you install it. Nothing is hidden.

It also means you can extend it: adding support for a tool is a single entry in a single file, and contributions are welcome. If something you use is missing, open a pull request — or just email us and we’ll add it.

What does it require?

macOS 14 Sonoma or later, on Apple silicon or Intel. The direct download is a universal binary, signed and notarized by Apple.
